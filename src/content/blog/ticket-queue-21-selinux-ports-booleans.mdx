<p>Yesterday's 403 turned out to be a file label. Today webadmin is back with three more denials, and none of them are about labels. Compliance wants httpd on port 8080, but the service will not even start, it dies with a bind error. The new app has to reach the database over the network, and httpd is blocked from making outbound connections at all. And the backup account is being refused read access to user homes, with the denial sitting right there in the audit log. Three problems, three different SELinux tools.</p>

<p>That is the whole lesson of part two: SELinux is more than file contexts. A non-standard port needs the port taught to the policy, an outbound connection needs a boolean flipped on, and a denial that fits none of the prebuilt fixes can be compiled into its own small policy module. Reach for the wrong one and you burn twenty minutes. Match the tool to the denial and each fix is two commands.</p>

<h2 id="port" class="pp-h2">Permit httpd on port 8080</h2>

<p>Reconfigure httpd to listen on 8080 and it fails to start, because SELinux only lets httpd bind to a known set of ports. Add 8080 to that set with <code>semanage port</code>, open the firewall too, and it starts.</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot"></div><div class="pp-code-dot"></div><div class="pp-code-dot"></div></div><div class="pp-code-lang">bash</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`sudo sed -i 's/^Listen 80$/Listen 8080/' /etc/httpd/conf/httpd.conf\nsudo systemctl restart httpd\n# Job for httpd.service failed. (98)Address already in use: could not bind\nsudo ausearch -m AVC -ts recent | tail -3\n# avc:  denied  { name_bind } for  comm="httpd" src=8080\n#   scontext=...:httpd_t:s0 tcontext=...:unreserved_port_t:s0\n\nsudo semanage port -l | grep http_port_t\n# http_port_t   tcp   80, 81, 443, 488, 8008, 8009, 8443, 9000\n# no 8080 in that list. that is the whole problem.\nsudo semanage port -a -t http_port_t -p tcp 8080\nsudo semanage port -l | grep http_port_t\n# http_port_t   tcp   8080, 80, 81, 443, 488, 8008, 8009, 8443, 9000\n\nsudo firewall-cmd --permanent --add-port=8080/tcp && sudo firewall-cmd --reload\nsudo systemctl restart httpd\nsystemctl is-active httpd    # active\ncurl -I http://localhost:8080`}</pre></div></div>

<div class="pp-note"><strong>note:</strong> SELinux blocking and firewall blocking are separate problems. The SELinux port rule lets httpd bind, the firewall rule lets traffic reach it. A non-standard port usually needs both.</div>

<h2 id="boolean" class="pp-h2">Allow outbound connections with a boolean</h2>

<p>Many common exceptions already exist as on/off switches called booleans. httpd making outbound network connections is one. The <code>-P</code> flag makes the change persist across reboots, and forgetting it is the classic mistake.</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot"></div><div class="pp-code-dot"></div><div class="pp-code-dot"></div></div><div class="pp-code-lang">bash</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`getsebool -a | grep httpd | head -20\ngetsebool httpd_can_network_connect    # off by default\n\nsudo setsebool -P httpd_can_network_connect on\ngetsebool httpd_can_network_connect    # on, and persistent because of -P`}</pre></div></div>

<h2 id="audit2allow" class="pp-h2">Build a module from denials with audit2allow</h2>

<p>When no file label, port, or boolean fits, you can turn the denials themselves into a policy module. Reproduce the denial, review what <code>audit2allow</code> proposes, then build and load the module. Always read the generated rules before loading, because a blind allow can grant something dangerous.</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot"></div><div class="pp-code-dot"></div><div class="pp-code-dot"></div></div><div class="pp-code-lang">bash</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`# reproduce a denial\nsudo touch /home/dev1/.test_file\nsudo -u svc_auto cat /home/dev1/.test_file 2>&1\n\n# see what would be allowed\nsudo ausearch -m AVC -ts recent | audit2allow -a\n\n# build a loadable module (creates backup_homes.te and .pp)\nsudo ausearch -m AVC -ts recent | audit2allow -M backup_homes\ncat backup_homes.te            # review before loading\n\nsudo semodule -i backup_homes.pp\nsudo semodule -l | grep backup_homes\n# remove later with: sudo semodule -r backup_homes`}</pre></div></div>
