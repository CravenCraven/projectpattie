<p>The compliance audit is in three days and logadmin1 has two gaps that will not survive it. journald is volatile, so every reboot wipes the system logs, and the auditors want history that outlives a restart, capped at 500MB so it cannot eat the disk. And the app logs, everything on facility <code>local5</code>, need their own file at <code>/var/log/app_local5.log</code> owned <code>0640 root:logadmin</code>. Then three specific journal queries the auditors will make you run live, and proof that <code>/var/log/messages</code> keeps at least four weeks.</p>

<p>The thing to hold in your head is that RHEL runs two logging systems side by side. journald collects everything and can be told to keep it. rsyslog writes the familiar text files under <code>/var/log</code> and routes by facility. logrotate decides how long any of it sticks around. Knowing which of the three owns which job is the entire ticket.</p>

<p>journald collects everything, the kernel, service output, and the syslog API, into a structured binary journal. It forwards to rsyslog, which writes the human-readable text files under <code>/var/log</code>. Both run by default, and they are complementary, not competitors. rsyslog routes by facility and priority.</p>

<h2 id="persistent" class="pp-h2">Make journald persistent</h2>

<p>By default journald writes to <code>/run</code>, which is wiped on reboot. Setting storage to persistent and giving it a size cap fixes both the loss and the risk of it eating the disk. Then restart journald so the change takes effect, which is the step people forget.</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot" style="background:#ff5f57"></div><div class="pp-code-dot" style="background:#febc2e"></div><div class="pp-code-dot" style="background:#28c840"></div></div><div class="pp-code-lang">bash</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`sudo mkdir -p /var/log/journal\nsudo cp /etc/systemd/journald.conf /etc/systemd/journald.conf.bak\nsudo sed -i 's/^#Storage=.*/Storage=persistent/' /etc/systemd/journald.conf\nsudo sed -i 's/^#SystemMaxUse=.*/SystemMaxUse=500M/' /etc/systemd/journald.conf\ngrep -E 'Storage|SystemMaxUse' /etc/systemd/journald.conf\n\nsudo systemctl restart systemd-journald\njournalctl --disk-usage\nls /var/log/journal/`}</pre></div></div>

<h2 id="logrotate" class="pp-h2">logrotate for retention</h2>

<p>logrotate handles keeping and compressing old logs. Inspect what already rotates <code>/var/log/messages</code>, then add a rule for the new file. The <code>postrotate</code> SIGHUP is important: rsyslog holds the old file open, so after logrotate moves it, rsyslog must reopen its handles or it keeps writing to the moved file.</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot" style="background:#ff5f57"></div><div class="pp-code-dot" style="background:#febc2e"></div><div class="pp-code-dot" style="background:#28c840"></div></div><div class="pp-code-lang">bash</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`cat /etc/logrotate.d/rsyslog          # controls /var/log/messages\nsudo logrotate -d /etc/logrotate.conf # dry run, shows what would happen\n\nsudo tee /etc/logrotate.d/app_local5 << 'EOF'\n/var/log/app_local5.log {\n    weekly\n    rotate 4\n    missingok\n    notifempty\n    compress\n    delaycompress\n    create 0640 root logadmin\n    postrotate\n        /usr/bin/systemctl kill -s HUP rsyslog.service > /dev/null 2>&1 || true\n    endscript\n}\nEOF\n\nsudo logrotate -d /etc/logrotate.d/app_local5    # validate`}</pre></div></div>
