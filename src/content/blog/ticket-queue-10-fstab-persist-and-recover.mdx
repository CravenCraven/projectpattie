<p><span class="c-light">The ticket:</span> dbadmin1 has two needs and a scar. First, <code>/srv/db</code> must mount automatically on boot using its UUID, not the device path, and it has to be tested without a reboot. Second, a second logical volume needs to be ext4 for a legacy app, mounted at <code>/srv/legacy</code>. And they want to learn the recovery flow, because a typo in fstab took a staging box down last week and needed remote hands.</p>

<p><span class="c-light">The real problem:</span> a bad fstab line can stop a machine from booting. The whole point of this ticket is persisting mounts safely and knowing how to recover when it goes wrong.</p>

<p><span class="c-light">What we are doing:</span> UUID-based fstab entries, an ext4 volume alongside the XFS one, and the broken-fstab recovery drill.</p>

<h2 id="concept-review" class="pp-h2">Concept review. The fstab fields.</h2>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot" style="background:#ff5f57"></div><div class="pp-code-dot" style="background:#febc2e"></div><div class="pp-code-dot" style="background:#28c840"></div></div><div class="pp-code-lang">bash</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`man fstab\nman mount\nman mkfs.xfs mkfs.ext4`}</pre></div></div>

<p>Each fstab line has six fields: the device, the mountpoint, the filesystem type, the mount options, a dump flag that is always 0, and a pass number that controls fsck order (0 for none, 1 for root, 2 for everything else).</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot" style="background:#ff5f57"></div><div class="pp-code-dot" style="background:#febc2e"></div><div class="pp-code-dot" style="background:#28c840"></div></div><div class="pp-code-lang">fstab fields</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`device         mountpoint   fstype   options    dump  pass\nUUID=xxxx      /srv/db      xfs      defaults   0     0`}</pre></div></div>

<p>Always use the UUID, not the device path. Device names like <code>/dev/sdb</code> are assigned by the kernel at boot and can shift when you add hardware. The UUID lives inside the filesystem itself and never moves.</p>

<h2 id="persist" class="pp-h2">Persist /srv/db by UUID</h2>

<p>Back up fstab before every edit. Then capture the UUID into a variable and append a clean line.</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot" style="background:#ff5f57"></div><div class="pp-code-dot" style="background:#febc2e"></div><div class="pp-code-dot" style="background:#28c840"></div></div><div class="pp-code-lang">bash</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`sudo cp /etc/fstab /etc/fstab.bak.$(date +%Y%m%d)\n\nDB_UUID=$(sudo blkid -s UUID -o value /dev/dbvg/dblv)\necho "UUID=$DB_UUID /srv/db xfs defaults 0 0" | sudo tee -a /etc/fstab\ntail -1 /etc/fstab`}</pre></div></div>

<h2 id="test" class="pp-h2">Test without rebooting</h2>

<p>This is the reboot test you can run safely. Unmount what is there, then let fstab mount everything. If <code>mount -a</code> works cleanly, the reboot will too.</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot" style="background:#ff5f57"></div><div class="pp-code-dot" style="background:#febc2e"></div><div class="pp-code-dot" style="background:#28c840"></div></div><div class="pp-code-lang">bash</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`sudo umount /srv/db\nmount | grep /srv/db    # should be empty now\n\nsudo mount -a\nmount | grep /srv/db    # mounted again, from fstab this time\ndf -h /srv/db`}</pre></div></div>

<h2 id="ext4" class="pp-h2">Add the legacy ext4 volume</h2>

<p>Same pattern, different filesystem. Create the volume, format ext4, and persist it by UUID.</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot" style="background:#ff5f57"></div><div class="pp-code-dot" style="background:#febc2e"></div><div class="pp-code-dot" style="background:#28c840"></div></div><div class="pp-code-lang">bash</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`sudo lvcreate -L 500M -n legacylv dbvg\nsudo mkfs.ext4 /dev/dbvg/legacylv\nsudo mkdir -p /srv/legacy\n\nLEGACY_UUID=$(sudo blkid -s UUID -o value /dev/dbvg/legacylv)\necho "UUID=$LEGACY_UUID /srv/legacy ext4 defaults 0 0" | sudo tee -a /etc/fstab\nsudo mount -a\ndf -hT /srv/legacy    # -T shows the filesystem type`}</pre></div></div>

<h2 id="recovery" class="pp-h2">The broken fstab recovery drill</h2>

<p>Practice this now, calmly, so you can do it under pressure later. Add a deliberately bad line, watch <code>mount -a</code> reject it, then recover from the backup. That same error at boot is what drops a machine into emergency mode.</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot" style="background:#ff5f57"></div><div class="pp-code-dot" style="background:#febc2e"></div><div class="pp-code-dot" style="background:#28c840"></div></div><div class="pp-code-lang">bash</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`sudo cp /etc/fstab /etc/fstab.working\n\n# add a bad line on purpose\necho "UUID=0000-bad /broken xfs defaults 0 0" | sudo tee -a /etc/fstab\nsudo mount -a    # error: cannot find the UUID. this is what blocks boot\n\n# recover: restore the good file and re-test\nsudo cp /etc/fstab.working /etc/fstab\nsudo mount -a    # clean again\nsudo rm /etc/fstab.working`}</pre></div></div>

<div class="pp-warn"><strong>warning:</strong> If a bad line does reach a reboot and the box lands in emergency mode, the recovery is: log in as root, remount root read-write with <code>mount -o remount,rw /</code>, fix or remove the bad line in <code>/etc/fstab</code>, then <code>systemctl reboot</code>. Knowing this is the difference between a two minute fix and a call to the data center.</div>
