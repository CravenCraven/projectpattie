<p><span class="c-light">The ticket:</span> auditor1 needs three reports out of <code>/etc/passwd</code> for the Q2 access audit. Every regular user with UID and shell, the three most common login shells with counts, and every account whose password is locked. Save them in <code>/srv/audit_reports/</code>. Also, <code>/etc/motd.bak</code> has the wrong company name throughout, and every "OldCorp" needs to become "Server1 Corp" in place, without breaking the file.</p>

<p><span class="c-light">The real problem:</span> nothing here is hard once you use the right tool for each slice. The exam loves asking for one specific column of a system file, so this is core muscle.</p>

<p><span class="c-light">What we are doing:</span> grep, awk, sed, cut, sort, and uniq on real system files, plus a safe in-place edit.</p>

<h2 id="report-1" class="pp-h2">Report one. Regular users.</h2>

<p>Real users start at UID 1000. Filter on the third field and print the fields you want, formatted so the auditor can read it.</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot" style="background:#ff5f57"></div><div class="pp-code-dot" style="background:#febc2e"></div><div class="pp-code-dot" style="background:#28c840"></div></div><div class="pp-code-lang">bash</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`# see it first\nawk -F: '$3 >= 1000 {print $1, $3, $7}' /etc/passwd\n\n# aligned columns, saved to the report\nsudo mkdir -p /srv/audit_reports\nsudo chown admin:auditors /srv/audit_reports\nsudo chmod 770 /srv/audit_reports\nawk -F: '$3 >= 1000 {printf "%-20s %-6s %s\\n", $1, $3, $7}' /etc/passwd \\\n  | sudo tee /srv/audit_reports/regular_users.txt\nsudo chgrp auditors /srv/audit_reports/regular_users.txt`}</pre></div></div>

<p><code>-F:</code> sets the delimiter, <code>$3</code> is the UID, <code>$1</code> the name, <code>$7</code> the shell. <code>printf</code> keeps the columns lined up.</p>

<h2 id="report-2" class="pp-h2">Report two. The top three shells.</h2>

<p>Build this one pipe at a time so you can watch it take shape. The order is deliberate, because <code>uniq -c</code> only collapses adjacent duplicates and needs sorted input.</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot" style="background:#ff5f57"></div><div class="pp-code-dot" style="background:#febc2e"></div><div class="pp-code-dot" style="background:#28c840"></div></div><div class="pp-code-lang">bash</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`cut -d: -f7 /etc/passwd                          # every shell\ncut -d: -f7 /etc/passwd | sort                   # sorted so duplicates sit together\ncut -d: -f7 /etc/passwd | sort | uniq -c         # counted\ncut -d: -f7 /etc/passwd | sort | uniq -c | sort -rn | head -3   # top three\n\n# save it\ncut -d: -f7 /etc/passwd | sort | uniq -c | sort -rn | head -3 \\\n  | sudo tee /srv/audit_reports/top_shells.txt\nsudo chgrp auditors /srv/audit_reports/top_shells.txt`}</pre></div></div>

<h2 id="report-3" class="pp-h2">Report three. Locked accounts.</h2>

<p>The password hash lives in <code>/etc/shadow</code>, not <code>/etc/passwd</code>, and a locked account has a leading <code>!</code> on the hash. This needs <code>sudo</code> to read.</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot" style="background:#ff5f57"></div><div class="pp-code-dot" style="background:#febc2e"></div><div class="pp-code-dot" style="background:#28c840"></div></div><div class="pp-code-lang">bash</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`sudo awk -F: '$2 ~ /^!/ {print $1}' /etc/shadow \\\n  | sudo tee /srv/audit_reports/locked_accounts.txt\nsudo chgrp auditors /srv/audit_reports/locked_accounts.txt\nsudo chmod 640 /srv/audit_reports/locked_accounts.txt   # shadow-derived, keep it tight`}</pre></div></div>

<p><code>$2 ~ /^!/</code> is an awk regex match: field two begins with <code>!</code>. Because it comes from shadow, lock the report down to the auditors group.</p>

<h2 id="sed-edit" class="pp-h2">The in-place edit, done safely</h2>

<p><code>sed -i</code> edits the file directly, which is exactly what is asked, and exactly what bites people who skip a backup. Always copy first.</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot" style="background:#ff5f57"></div><div class="pp-code-dot" style="background:#febc2e"></div><div class="pp-code-dot" style="background:#28c840"></div></div><div class="pp-code-lang">bash</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`# build the test file\nsudo bash -c 'cat > /etc/motd.bak << EOF\nWelcome to OldCorp Production Server\nFor support, contact OldCorp IT\nThis system is property of OldCorp.\nEOF'\n\n# back up, then replace globally, in place, then diff to confirm\nsudo cp /etc/motd.bak /etc/motd.bak.backup\nsudo sed -i 's/OldCorp/Server1 Corp/g' /etc/motd.bak\nsudo diff /etc/motd.bak.backup /etc/motd.bak`}</pre></div></div>

<p><code>s/old/new/g</code> substitutes every match on each line, and the <code>diff</code> against the backup proves you changed only what you meant to.</p>
