<p>Phase 3 starts here: the dev team's stack moves into containers, and cuser1 wants the first two stood up. An nginx serving the same <code>/srv/webcontent</code> that has followed us since the shared-folder ticket on day three, with host port 8080 mapped to the container's 80, and a redis named <code>dev-cache</code> with its data on a real volume at <code>/srv/cuser1/redis-data</code>. Both run rootless as the unprivileged <code>cuser1</code>, no root containers anywhere, and SELinux stays enforcing.</p>

<p>Two things bite everyone on rootless podman, and this ticket walks straight into both. A bind-mount without the SELinux relabel flag hands the container a directory it is not allowed to read, so nginx 403s. And a rootless user cannot bind a port under 1024, so anyone who reflexively maps port 80 gets permission denied. Map above 1024, remember the <code>:Z</code>, and the rest is easy.</p>

<h2 id="concept-review" class="pp-h2">Concept review. Why podman, and the run flags.</h2>

<p>On RHEL, podman is rootless by default, so each user has their own container store, and there is no daemon, each container is a child of podman itself. The CLI matches docker closely. The run flags you use constantly are below.</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot"></div><div class="pp-code-dot"></div><div class="pp-code-dot"></div></div><div class="pp-code-lang">podman run flags</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`-d               detached, run in the background\n--name NAME      name the container\n-p host:cont     port map, e.g. -p 8080:80\n-v host:cont:Z   volume mount; :Z relabels for SELinux\n-e KEY=VAL       environment variable\n-it              interactive with a TTY\n--rm             auto-remove on exit`}</pre></div></div>

<h2 id="setup" class="pp-h2">Switch to the container user and pull</h2>

<p><code>enable-linger</code> lets the user's services keep running when they are logged out, which you will need for boot persistence later. Then work as the user and pull the images by their fully qualified names, since podman does not assume Docker Hub.</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot"></div><div class="pp-code-dot"></div><div class="pp-code-dot"></div></div><div class="pp-code-lang">bash</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`sudo loginctl enable-linger cuser1\nsudo -iu cuser1\npodman info | head -20    # confirms rootless\n\npodman pull docker.io/library/nginx:latest\npodman pull docker.io/library/redis:latest\npodman images`}</pre></div></div>

<h2 id="nginx" class="pp-h2">Run nginx with a bind-mount and port map</h2>

<p>The <code>:Z</code> on the volume is the part that matters. It tells podman to relabel the host directory with a private SELinux container label so the container can read it. Leave it off and SELinux denies access, giving you a 403.</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot"></div><div class="pp-code-dot"></div><div class="pp-code-dot"></div></div><div class="pp-code-lang">bash</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`podman run -d \\\n    --name dev-web \\\n    -p 8080:80 \\\n    -v /srv/webcontent:/usr/share/nginx/html:ro,Z \\\n    nginx:latest\n\npodman ps\ncurl http://localhost:8080/`}</pre></div></div>

<h2 id="redis" class="pp-h2">Run redis with a persistent volume</h2>

<p>The volume keeps the data across container restarts, and <code>:Z</code> again handles SELinux.</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot"></div><div class="pp-code-dot"></div><div class="pp-code-dot"></div></div><div class="pp-code-lang">bash</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`mkdir -p /srv/cuser1/redis-data\npodman run -d \\\n    --name dev-cache \\\n    -v /srv/cuser1/redis-data:/data:Z \\\n    -p 6379:6379 \\\n    redis:latest redis-server --appendonly yes\n\npodman ps\npodman logs dev-cache | tail`}</pre></div></div>

<p>These are the failures worth reproducing once so you recognize them instantly.</p>
