<p><span class="c-light">The ticket:</span> a fresh second disk is attached to the box. dbadmin1 needs three partitions off it. One large one for database files that will become an LVM physical volume, one roughly 512MB for swap, and one roughly 1GB flagged as a plain Linux filesystem. Pick MBR or GPT, document why, and make sure the kernel actually sees the partitions before you hand it off.</p>

<p><span class="c-light">The real problem:</span> partitioning is easy to do and easy to do wrong. The two things people miss are setting the correct type code so LVM and swap tools recognize the partition, and telling the running kernel to re-read the table so the new partitions actually appear.</p>

<p><span class="c-light">What we are doing:</span> partitioning with <code>gdisk</code> for GPT (and <code>fdisk</code> for MBR), setting type codes, and refreshing the kernel view.</p>

<h2 id="the-ticket" class="pp-h2">The ticket</h2>

<p>This step is the one to be careful with. You need a real second disk, and you must be certain which device it is before you write to it. Writing to the wrong disk is how you lose a system.</p>

<p>MBR is the old scheme. It caps out at 2TB and four primary partitions, and it keeps no backup of the partition table. GPT is the modern scheme. It handles enormous disks, up to 128 partitions, and stores a backup table. On RHEL 9 the default and the right choice is GPT, so that is what this ticket uses. <code>gdisk</code> is the GPT tool, <code>fdisk</code> is the MBR tool.</p>

<p>The type code tells the system what a partition is for. Set it wrong and LVM or swap will not recognize the partition later.</p>

<h2 id="partprobe" class="pp-h2">Make the kernel re-read the table</h2>

<p>If <code>lsblk</code> does not show the new partitions, the running kernel is still holding the old table in memory. <code>partprobe</code> forces a re-read without a reboot. This is the reflex that saves you on the exam.</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot" style="background:#ff5f57"></div><div class="pp-code-dot" style="background:#febc2e"></div><div class="pp-code-dot" style="background:#28c840"></div></div><div class="pp-code-lang">bash</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`sudo partprobe /dev/sdb\nlsblk /dev/sdb\nsudo udevadm settle    # if device nodes lag behind`}</pre></div></div>

<h2 id="fdisk" class="pp-h2">The MBR alternative with fdisk</h2>

<p>Worth knowing both tools. <code>fdisk</code> drives MBR the same way, with slightly different keys. Only run this on a spare disk you are willing to wipe.</p>
