<p><span class="c-light">The ticket:</span> people on the DB team have been dumping massive query results to <code>/srv/db</code>, and there have already been two close calls with the disk filling. dbadmin1 wants quotas. <code>dbadmin1</code> gets 500MB soft and 600MB hard, <code>dbreader</code> gets 100MB soft and 150MB hard, and the <code>dbadmins</code> group gets 1GB soft and 1.2GB hard across all members. Finish with a report of everyone's usage.</p>

<p><span class="c-light">The real problem:</span> XFS quotas cannot just be switched on. They need mount options in fstab and a remount before any limit will take effect. Miss that and every <code>limit</code> command silently does nothing.</p>

<p><span class="c-light">What we are doing:</span> enabling XFS quotas, setting per-user and per-group limits, and reporting usage.</p>

<h2 id="concept-review" class="pp-h2">Concept review. Soft, hard, and grace.</h2>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot"></div><div class="pp-code-dot"></div><div class="pp-code-dot"></div></div><div class="pp-code-lang">bash</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`man xfs_quota mount`}</pre></div></div>

<p>A soft limit is a warning threshold. The user can go over it, but only for a grace period, seven days by default. A hard limit is an absolute ceiling, and a write that would cross it fails on the spot. Quotas can be counted in blocks, which is disk space, or in inodes, which is number of files. This ticket is all block quotas.</p>

<p>XFS quotas are turned on by mount options: <code>usrquota</code> for user quotas and <code>grpquota</code> for group quotas. The command to set and read them follows one pattern.</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot"></div><div class="pp-code-dot"></div><div class="pp-code-dot"></div></div><div class="pp-code-lang">the pattern</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`xfs_quota -x -c 'COMMAND' /mountpoint\n# -x  expert mode, needed to set limits, timers, and state\n# -c  the command to run`}</pre></div></div>

<h2 id="enable" class="pp-h2">Enable quotas in fstab and remount</h2>

<p>Add the two options to the <code>/srv/db</code> line, then remount. XFS quotas can only be activated by a remount, not on the fly.</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot"></div><div class="pp-code-dot"></div><div class="pp-code-dot"></div></div><div class="pp-code-lang">bash</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`grep '/srv/db' /etc/fstab\nsudo cp /etc/fstab /etc/fstab.bak.$(date +%Y%m%d_%H%M)\n\n# add usrquota,grpquota to the /srv/db line's options\nsudo sed -i '\\|/srv/db| s|defaults|defaults,usrquota,grpquota|' /etc/fstab\ngrep '/srv/db' /etc/fstab\n\n# remount to activate (unmount then mount, not remount)\nsudo umount /srv/db\nsudo mount /srv/db\nmount | grep /srv/db    # should now include usrquota,grpquota`}</pre></div></div>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot"></div><div class="pp-code-dot"></div><div class="pp-code-dot"></div></div><div class="pp-code-lang">bash</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`sudo xfs_quota -x -c 'limit bsoft=500m bhard=600m dbadmin1' /srv/db\nsudo xfs_quota -x -c 'limit bsoft=100m bhard=150m dbreader' /srv/db\n\nsudo xfs_quota -x -c 'quota -u dbadmin1' /srv/db\nsudo xfs_quota -x -c 'quota -u dbreader' /srv/db`}</pre></div></div>

<h2 id="test" class="pp-h2">Prove the hard limit works</h2>

<p>A quota you have not tested is a quota you do not trust. Write under the limit, then try to blow past it and watch the write stop.</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot"></div><div class="pp-code-dot"></div><div class="pp-code-dot"></div></div><div class="pp-code-lang">bash</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`sudo mkdir -p /srv/db/dbadmin1_workspace\nsudo chown dbadmin1:dbadmins /srv/db/dbadmin1_workspace\n\n# under the soft limit, succeeds\nsudo -u dbadmin1 dd if=/dev/zero of=/srv/db/dbadmin1_workspace/test_400mb bs=1M count=400\nsudo xfs_quota -x -c 'quota -u dbadmin1' /srv/db\n\n# past the hard limit, stops with 'Disk quota exceeded'\nsudo -u dbadmin1 dd if=/dev/zero of=/srv/db/dbadmin1_workspace/test_250mb bs=1M count=250\nsudo xfs_quota -x -c 'quota -u dbadmin1' /srv/db\nsudo rm /srv/db/dbadmin1_workspace/test_*`}</pre></div></div>
