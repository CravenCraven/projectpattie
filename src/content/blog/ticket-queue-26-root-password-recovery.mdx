<p>The phone goes at 2:47 AM. During the DR drill someone changed root's password and never wrote it down, there is no second admin with sudo, and root SSH was turned off two tickets ago, so there is no working login left. The box is up and serving traffic and completely locked to you. ops1 wants it back without a reinstall, and the clock is running the whole time.</p>

<p>This is a memorize-it-cold procedure: five minutes once you know it, a very long night if you do not. Every step has a reason, and the one people skip, the SELinux relabel, is exactly what locks you out a second time even after the password is reset. Console access only, and snapshot the VM before you touch anything.</p>

<h2 id="the-ticket" class="pp-h2">The ticket</h2>

<p>This lab reboots the machine and needs console access, not SSH. Snapshot the VM before you start so you have a way back if anything goes sideways.</p>

<h2 id="concept-review" class="pp-h2">Concept review. The recovery flow, and why each step.</h2>

<p><code>rd.break</code> stops the boot after the initramfs but before it switches to the real root. At that point the real root is mounted read-only at <code>/sysroot</code>. You remount it writable, <code>chroot</code> into it so <code>passwd</code> can find the real <code>/etc/shadow</code>, change the password, and then trigger a relabel because the freshly written shadow file ends up with the wrong SELinux context.</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot" style="background:#ff5f57"></div><div class="pp-code-dot" style="background:#febc2e"></div><div class="pp-code-dot" style="background:#28c840"></div></div><div class="pp-code-lang">the recovery flow</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`1  reboot, hold a key at GRUB\n2  press e to edit the boot entry\n3  on the linux line, add: rd.break\n4  Ctrl-X to boot\n5  at switch_root:/# you are in the initramfs, root not switched yet\n6  mount -o remount,rw /sysroot\n7  chroot /sysroot\n8  passwd root\n9  touch /.autorelabel     <- the step people forget\n10 exit    (leaves chroot)\n11 exit    (leaves initramfs, boot continues and relabels)`}</pre></div></div>

<h2 id="rd-break" class="pp-h2">Break into the initramfs at GRUB</h2>

<p>Reboot from the console. When GRUB appears you have a few seconds. Highlight the default entry, press <code>e</code>, find the line that starts with <code>linux</code>, and add <code>rd.break</code> at the end of it, then boot the edited entry.</p>

<h2 id="chroot" class="pp-h2">Remount and chroot</h2>

<p>The real root is mounted read-only at <code>/sysroot</code>. Remount it read-write, then chroot so the rest of the commands act on the real system.</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot" style="background:#ff5f57"></div><div class="pp-code-dot" style="background:#febc2e"></div><div class="pp-code-dot" style="background:#28c840"></div></div><div class="pp-code-lang">bash</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`mount | grep sysroot          # shows /sysroot mounted ro\nmount -o remount,rw /sysroot\nchroot /sysroot              # now effectively root in the real system`}</pre></div></div>

<h2 id="passwd" class="pp-h2">Reset the password and relabel</h2>

<p>Set the new password, then create <code>/.autorelabel</code>. That file tells the next boot to relabel every file to match current policy, which fixes the context on the shadow file you just changed.</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot" style="background:#ff5f57"></div><div class="pp-code-dot" style="background:#febc2e"></div><div class="pp-code-dot" style="background:#28c840"></div></div><div class="pp-code-lang">bash</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`passwd root                  # enter the new password twice\ngrep root /etc/shadow | head -1    # hash is now a fresh $6$ entry\n\ntouch /.autorelabel          # critical, or you cannot log in after boot`}</pre></div></div>

<h2 id="verify" class="pp-h2">Exit, reboot, verify</h2>

<p>Two exits: the first leaves the chroot, the second leaves the initramfs shell so the boot continues. The relabel adds a few minutes and then the system reboots itself once more and comes up clean.</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot" style="background:#ff5f57"></div><div class="pp-code-dot" style="background:#febc2e"></div><div class="pp-code-dot" style="background:#28c840"></div></div><div class="pp-code-lang">bash</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`exit    # leave chroot\nexit    # leave initramfs, boot continues\n\n# after it relabels and reboots, log in as root with the new password\ngetenforce    # Enforcing\nsestatus`}</pre></div></div>

<h2 id="miss" class="pp-h2">The step everyone forgets</h2>

<p>If you skip <code>touch /.autorelabel</code>, the system boots but SELinux denies access to the relabeled-wrong shadow file, and you cannot log in even with the correct password. If that happens, redo <code>rd.break</code> and fix just that one file.</p>
