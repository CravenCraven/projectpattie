<h2 class="pp-h2" id="start">How this started</h2>

<p>fsi-scraper is the project on my resume. It takes a free 1970s Portuguese course from the US Foreign Service Institute and turns it into data the rest of the Brasil homelab can use. Flashcards, the demo page, and later the slang database.</p>

<p>Until this week it had one stage. It could find the files. It could not download them, read them, or store anything. On a resume that is a list of URLs.</p>

<p>This post is the rest of the pipeline. Five stages, each one small, each one with one job:</p>

<p>Every stage can be run again without breaking anything. That turned out to be the theme of the whole afternoon, so it comes up a lot below.</p>

<h2 class="pp-h2" id="discover">Discover: how the first stage already worked</h2>

<p>I wrote discover weeks ago. Before adding stages on top of it, I went back and read it properly.</p>

<h3 class="pp-h3">One interface for every source</h3>

<p>Every course gets a parser that implements two methods:</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot"></div><div class="pp-code-dot"></div><div class="pp-code-dot"></div></div><div class="pp-code-lang">python</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`class CourseParser(ABC):\n    @abstractmethod\n    def parse(self, html: str, page_url: str) -> Iterator[Resource]:\n        """Yield one Resource per downloadable asset found in \`html\`."""\n\n    def follow(self, html: str, page_url: str) -> Iterable[str]:\n        """Yield further page URLs to crawl. Default: single-page course."""\n        return ()`}</pre></div></div>

<p><code>parse</code> finds files on a page. <code>follow</code> finds more pages worth visiting. The FAST course is a single page, so it only needs <code>parse</code>. Another course might be an index page plus a page per unit, so it would also implement <code>follow</code>. The crawl loop does not care which. It keeps a queue of pages and a set of pages it has already visited, so nothing gets fetched twice even if two pages link to each other.</p>

<h3 class="pp-h3">Polite by default</h3>

<ul>
  <li><strong>A 1 second delay between requests.</strong> This is a free site run by volunteers. It does not need me hammering it while I debug.</li>
  <li><strong>A User-Agent that says who I am</strong>, with a link to the repo. If my scraper ever caused a problem, the site owner can see what it is and how to reach me.</li>
  <li><strong>A page cache.</strong> With <code>--cache .cache</code>, every page I fetch gets saved. Rerunning discover a hundred times while I work makes one request, not a hundred.</li>
</ul>

<h3 class="pp-h3">Read the URL, not the page</h3>

<p>The obvious way to scrape a course page is to read its HTML table: this row is lesson 1, this cell is the download link. The problem is the table is the part of the page most likely to change when the site gets redesigned.</p>

<p>So discover ignores the layout and reads the download URLs themselves. The files live on a CDN, and the lesson number and volume are right there in the path:</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot"></div><div class="pp-code-dot"></div><div class="pp-code-dot"></div></div><div class="pp-code-lang">python</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`VOLUME_IN_PATH = re.compile(r"/FAST/Volume\\s+(\\d+)/", re.IGNORECASE)\nAUDIO_FILE = re.compile(r"Lesson\\s+(\\d{1,2})\\s*([AB])?\\.mp3$", re.IGNORECASE)\nPDF_FILE = re.compile(r"Volume\\s+(\\d+)\\.pdf$", re.IGNORECASE)`}</pre></div></div>

<p>One catch. A URL cannot contain a space, so <code>Volume 1</code> travels as <code>Volume%201</code>. A pattern looking for a space will never match that. Discover decodes the path with <code>unquote</code> first, so both forms come out as <code>Volume 1</code> before any pattern sees them.</p>

<h2 class="pp-h2" id="fetch">Fetch: downloading without trusting the network</h2>

<p>Downloading a file sounds like one line. It is, until the connection drops halfway through a 16 MB PDF and you are left with a file that has the right name, the right extension, and half the pages. Fetch is built around not letting that happen.</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot"></div><div class="pp-code-dot"></div><div class="pp-code-dot"></div></div><div class="pp-code-lang">python</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`def download(fetcher: Fetcher, resource: Resource, root: Path) -> Fetched:\n    dest = target_path(root, resource)\n    if dest.exists():\n        return Fetched(resource, dest, dest.stat().st_size, sha256_of(dest),\n                       downloaded=False)\n\n    dest.parent.mkdir(parents=True, exist_ok=True)\n    part = dest.with_name(dest.name + ".part")\n    digest = hashlib.sha256()\n    size = 0\n\n    with fetcher.stream(resource.url) as response:\n        expected = response.headers.get("Content-Length")\n        if response.headers.get("Content-Encoding"):\n            expected = None  # compressed on the wire; length won't match\n        with part.open("wb") as out:\n            for chunk in response.iter_content(CHUNK):\n                out.write(chunk)\n                digest.update(chunk)\n                size += len(chunk)\n\n    if expected is not None and int(expected) != size:\n        part.unlink()\n        raise OSError(f"incomplete download: got {size} of {expected} bytes")\n\n    part.replace(dest)\n    return Fetched(resource, dest, size, digest.hexdigest(), downloaded=True)`}</pre></div></div>

<h3 class="pp-h3">Stream it, 64 KB at a time</h3>

<p><code>stream=True</code> tells requests not to pull the whole file into memory. The loop reads 64 KB, writes it, reads the next 64 KB. A 16 MB PDF would fit in memory fine. 330 MB of audio on a laptop that is also a Kubernetes node is a worse idea. Same code either way.</p>

<h3 class="pp-h3">Write to .part, then rename</h3>

<p>The download goes to <code>Volume 1.pdf.part</code>. Only when every byte has arrived does it get renamed to <code>Volume 1.pdf</code>. A rename within one disk is a single step. There is no moment where the real filename points at half a file.</p>

<p>If the connection dies, what is left is a <code>.part</code> file. That name says exactly what it is. And because the check at the top looks for the real filename, the next run starts that file over instead of skipping it.</p>

<h3 class="pp-h3">Check the size</h3>

<p>The server sends a <code>Content-Length</code> header: how many bytes it is about to send. Fetch counts what actually arrived. If they do not match, it deletes the <code>.part</code> and reports a failure.</p>

<p>There is one exception in the code. If the server compresses the file on the way (<code>Content-Encoding</code>), <code>Content-Length</code> is the compressed size, and requests hands back the uncompressed bytes. They would never match. So in that case the check is skipped instead of failing every time.</p>

<h3 class="pp-h3">Fingerprint it while it downloads</h3>

<p>Each chunk also goes into a SHA-256 hash. By the time the download finishes, the fingerprint is done too, without reading the file a second time. That fingerprint is how I will tell, months from now, whether the file on the site changed or whether my copy got damaged.</p>

<h2 class="pp-h2" id="parse">Parse: every lesson broke a different rule</h2>

<h3 class="pp-h3">The shape of a lesson</h3>

<p>Every lesson in the book follows the same layout:</p>

<ul>
  <li>A scene page: <code>I. Setting the Scene</code>, then <code>LESSON 1</code>, the location (<code>AT THE HOTEL</code>) and the title (<code>Checking In</code>).</li>
  <li>A dialog page under <code>III. Seeing It</code>. One line per speaker. <code>A.</code> is the American, <code>B.</code> is the Brazilian.</li>
  <li>The dialog ends at the page footer, a lesson and page number like <code>2.2</code>.</li>
  <li>Then exercise pages like Filling in the Blanks, which are mostly underscores. Those get skipped.</li>
</ul>

<h3 class="pp-h3">The patterns</h3>

<p>Here is every pattern the parser uses, and the OCR mistake each one was written for:</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot"></div><div class="pp-code-dot"></div><div class="pp-code-dot"></div></div><div class="pp-code-lang">python</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`LESSON = re.compile(r"\\bLESSON\\s*(\\d{1,2})\\b")\nHEADER = re.compile(r"^BRAZI\\w*\\s+PORTUGUESE\\s+FAST$")\nSEEING_IT = re.compile(r"Seeing\\s+It\\b")\nNEXT_SECTION = re.compile(r"^[IVX1l]+\\s*\\.\\s+[A-Z][a-z]")  # "IV. Taking It Apart"\nFOOTER = re.compile(r"^\\d{1,2}\\s*[.\\-]\\s*\\S{1,3}$")  # "2.2", "5.t", "13 -4"\nSPEAKER = re.compile(r"^(A|B|[B8]\\s?[12])\\s?\\.\\s+(.*)$")\nDIRECTION = re.compile(r"^\\(.*\\)$")  # "(A few minutes later)"`}</pre></div></div>

<ul>
  <li><code>LESSON\s*</code> with a star, not a plus. Star means zero or more spaces, so <code>LESSON3</code> still matches.</li>
  <li><code>BRAZI\w*</code> matches the page header however the OCR spelled it: BRAZILlAN, BRAZIUAN. Those lines get stripped before anything else looks at the page.</li>
  <li><code>Seeing It</code> matches the words, never the number. The number is <code>111</code> or <code>III</code> depending on the page.</li>
  <li><code>NEXT_SECTION</code> allows <code>1</code> and <code>l</code> alongside real Roman numerals, for the same reason.</li>
  <li><code>FOOTER</code> is loose on purpose. The page number came out as <code>2.2</code>, <code>5.t</code> and <code>13 -4</code>.</li>
  <li><code>SPEAKER</code> accepts <code>A</code>, <code>B</code>, and B1 or B2 written with an 8 and an optional space. More on that one below.</li>
</ul>

<h3 class="pp-h3">What broke when I ran it against all 681 pages</h3>

<p>The first version worked on lesson 1. Then I ran it against both books and every assumption broke at least once.</p>

<ul>
  <li><strong>Lesson 3 was missing.</strong> The OCR wrote <code>LESSON3</code> with no space, and the first pattern needed one.</li>
  <li><strong>Lesson 13 has three people.</strong> It is a party, with two Brazilians, B1 and B2. OCR reads B as 8, so they came out as <code>81.</code> and <code>82.</code>, and once as <code>B 1.</code> The parser turns all of those into <code>B1</code> and <code>B2</code>. Without that, lesson 13 looked like a monologue.</li>
  <li><strong>Lesson 30 has no Sample Dialog heading.</strong> Every other lesson does. If the parser had anchored on that heading, lesson 30 would have come back empty. It anchors on the section instead, <code>Seeing It</code>, which every lesson has.</li>
  <li><strong>Stage directions.</strong> <code>(A few minutes later)</code> sits between two lines in lesson 30. I kept it, with no speaker, because it is part of the scene.</li>
  <li><strong>Long lines wrap.</strong> A sentence that runs past the edge of the page continues on the next line with no speaker. The parser glues it back onto the line before.</li>
</ul>

<h2 class="pp-h2" id="postgres">Why Postgres and not SQLite</h2>

<p>For one person and 351 lines, SQLite would be fine. It is one file and needs nothing running. I went with Postgres for two reasons.</p>

<p><strong>One setting switches where it runs.</strong> The code reads a single environment variable, <code>DATABASE_URL</code>. On my Mac it falls back to a local Postgres in Docker. On the cluster it will point at CloudNativePG. Same code, one variable, nothing else changes.</p>

<p>Locally, Postgres is one Docker Compose file:</p>

<h2 class="pp-h2" id="schema">The schema, one decision at a time</h2>

<p>I did not design the first table from scratch. The scraper already had a <code>Resource</code> record, one per downloadable file. The table is that record, field for field, so one Resource is one row and there is nothing to translate.</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot"></div><div class="pp-code-dot"></div><div class="pp-code-dot"></div></div><div class="pp-code-lang">sql</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`CREATE TABLE IF NOT EXISTS resource (\n    id             bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,\n    source         text        NOT NULL,\n    provider       text        NOT NULL,\n    course         text        NOT NULL,\n    kind           text        NOT NULL CHECK (kind IN ('pdf', 'audio', 'zip')),\n    url            text        NOT NULL UNIQUE,\n    filename       text        NOT NULL,\n    title          text        NOT NULL,\n    section        text,\n    ordinal        integer,\n    part           text,\n    declared_bytes bigint,\n    discovered_at  timestamptz NOT NULL DEFAULT now()\n);`}</pre></div></div>

<ul>
  <li><strong><code>url</code> is UNIQUE.</strong> The URL is the natural key. It comes straight off the page, it never changes, and it points at exactly one file. Unique means discover can run a hundred times and never create a duplicate row.</li>
  <li><strong><code>id</code> as well.</strong> A small number is cheaper for other tables to point at than a long URL. The two new tables point at <code>id</code>, never at <code>url</code>.</li>
  <li><strong><code>CHECK (kind IN (...))</code></strong> matches <code>Kind = Literal["pdf", "audio", "zip"]</code> in the Python. In Python that is only a hint, and nothing stops a bad value unless I run a type checker. The database refuses it every time, no matter which program writes the row.</li>
  <li><strong><code>NOT NULL</code> follows the Python.</strong> Fields with no default in the record are required. Fields that default to <code>None</code> are allowed to be empty.</li>
  <li><strong><code>timestamptz</code></strong> stores the moment in UTC with the zone attached. After the Navidrome timezone mess, I wanted that settled at the database level.</li>
</ul>

<p>Then the two tables for the parsed text:</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot"></div><div class="pp-code-dot"></div><div class="pp-code-dot"></div></div><div class="pp-code-lang">sql</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`CREATE TABLE IF NOT EXISTS lesson (\n    id        bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,\n    course    text    NOT NULL,\n    number    integer NOT NULL,\n    location  text    NOT NULL,\n    title     text    NOT NULL,\n    UNIQUE (course, number)\n);\n\nCREATE TABLE IF NOT EXISTS dialog_line (\n    id        bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,\n    lesson_id bigint  NOT NULL REFERENCES lesson(id) ON DELETE CASCADE,\n    seq       integer NOT NULL,\n    speaker   text,\n    text      text    NOT NULL,\n    page      integer NOT NULL,\n    UNIQUE (lesson_id, seq)\n);`}</pre></div></div>

<ul>

  <li><strong><code>REFERENCES lesson(id)</code>.</strong> A dialog line cannot point at a lesson that does not exist.</li>

<h2 class="pp-h2" id="export">Export: the website never touches the database</h2>

<p>The <a href="/brasil/demo">demo page</a> is going to show real lessons. The obvious way to do that is to have the website read the database. There are three reasons it does not.</p>

<ul>
  <li><strong>It cannot reach it.</strong> projectpattie.com runs on Cloudflare. The database runs on a laptop in my house. Connecting them means opening the database to the internet, and then anyone can try to log in to it.</li>
  <li><strong>The site is static.</strong> It gets built once when I push. After that there is no program running that could go ask a database a question when someone visits.</li>
  <li><strong>The site should stay up when the homelab does not.</strong> My nodes are laptops. They sleep, they reboot, I move them. The portfolio should not go down with them.</li>
</ul>

<p>So <code>export</code> reads three lessons back out of Postgres and writes a JSON file into the website repo. The site will read the file at build time.</p>

<h3 class="pp-h3">Read it back from the database</h3>

<p>Export could have taken the lessons straight from the parser. It reads from Postgres instead, on purpose. The file is proof that the whole chain worked: the files came down, the PDFs parsed, the rows landed, and they come back out the way they went in.</p>

<p>The export has no timestamp, and every query has an <code>ORDER BY</code>. Export the same data twice and you get the same file, byte for byte. It also writes with <code>ensure_ascii=False</code>, so <code>às</code> stays <code>às</code> instead of turning into <code>\u00e0s</code>, which keeps the file readable in a diff.</p>

<h2 class="pp-h2" id="audio">Where the audio goes</h2>

<p>34 mp3s, about 330 MB. Three options:</p>

<ul>
  <li><strong>In Navidrome's music volume.</strong> No. They would show up in my music library next to Astrud Gilberto as if they were albums.</li>
  <li><strong>In the database.</strong> No. 330 MB of binary data in Postgres makes every backup huge and every query slower. A very common mistake.</li>
  <li><strong>Their own volume on the cluster, with the database holding the path to each file.</strong> Yes.</li>
</ul>

<p>Files live on disk and facts about files live in the database. That is the same split Navidrome already uses for my music. Locally they sit in <code>data/raw/.../audio/</code> for now. The volume gets created when fsi-scraper moves onto the cluster, and since local-path volumes cannot grow after they are created, it gets sized with room to spare.</p>

</ul>
