<p>The pen test report landed with one finding flagged critical and in red: SSH still accepts passwords. secadmin wants it closed before Friday. Key-based auth for the admin account, passwords off globally, root login over SSH off, and access narrowed to two named users plus the <code>sysadmins</code> group. The line in the ticket that matters most is the last one: test it twice before you drop the session you are working in.</p>

<p>Every step on this ticket can lock you out of the box, and root SSH is already off, so there is no side door if you do. The discipline is not optional: validate the config with <code>sshd -t</code> before you reload, and prove a brand new session works before you close the one you have.</p>

<div class="pp-warn"><strong>warning:</strong> Keep a second SSH session open the entire time. Edit the config, validate with <code>sshd -t</code>, reload, then log in from a brand new session before you close the one you have. If the new one fails, you still have the old one to fix it.</div>

<h2 id="concept-review" class="pp-h2">Concept review. Keys and the permissions that break them.</h2>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot"></div><div class="pp-code-dot"></div><div class="pp-code-dot"></div></div><div class="pp-code-lang">bash</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`man ssh\nman sshd_config\nman ssh-keygen`}</pre></div></div>

<p>Key auth uses a pair: a private key that never leaves your machine and a public key you place on the server. SSH is strict about permissions and will silently refuse keys if they are too loose. The directory must be 700, the private key and <code>authorized_keys</code> must be 600, and the public key can be 644.</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot"></div><div class="pp-code-dot"></div><div class="pp-code-dot"></div></div><div class="pp-code-lang">required permissions</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`~/.ssh                    700   only the owner can enter\n~/.ssh/authorized_keys    600   only the owner can read\n~/.ssh/id_ed25519         600   the private key, critical\n~/.ssh/id_ed25519.pub     644   public, fine to be readable`}</pre></div></div>

<h2 id="keygen" class="pp-h2">Generate a key pair</h2>

<p>ed25519 is the modern default on RHEL 9: smaller and faster than RSA at equivalent strength.</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot"></div><div class="pp-code-dot"></div><div class="pp-code-dot"></div></div><div class="pp-code-lang">bash</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`ssh-keygen -t ed25519 -C "admin@workstation" -f ~/.ssh/id_ed25519\n# press enter for no passphrase, or set one (recommended)\nls -la ~/.ssh    # id_ed25519 (600) and id_ed25519.pub (644)`}</pre></div></div>

<h2 id="distribute" class="pp-h2">Distribute the public key</h2>

<p><code>ssh-copy-id</code> is the easy path and prompts for the password one final time. After that, login is passwordless.</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot"></div><div class="pp-code-dot"></div><div class="pp-code-dot"></div></div><div class="pp-code-lang">bash</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`ssh-copy-id -i ~/.ssh/id_ed25519.pub admin@server1\n\n# manual alternative:\ncat ~/.ssh/id_ed25519.pub | ssh admin@server1 \\\n    'mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys'\n\nssh admin@server1 hostname    # should connect with no password prompt`}</pre></div></div>

<h2 id="harden" class="pp-h2">Harden sshd with a drop-in</h2>

<p>Write a drop-in in <code>/etc/ssh/sshd_config.d/</code> rather than editing the main file. Validate with <code>sshd -t</code> before you reload, and use <code>reload</code> not <code>restart</code> so existing sessions are not dropped.</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot"></div><div class="pp-code-dot"></div><div class="pp-code-dot"></div></div><div class="pp-code-lang">bash</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`sudo cp /etc/ssh/sshd_config /etc/ssh/sshd_config.bak.$(date +%Y%m%d)\n\nsudo tee /etc/ssh/sshd_config.d/99-hardening.conf << 'EOF'\nPasswordAuthentication no\nKbdInteractiveAuthentication no\nPermitRootLogin no\nAllowUsers admin student\nAllowGroups sysadmins\nEOF\n\nsudo sshd -t              # no output means the config is valid\nsudo systemctl reload sshd\nsystemctl is-active sshd`}</pre></div></div>

<div class="pp-note"><strong>note:</strong> <code>KbdInteractiveAuthentication no</code> matters. Without it, password-style login can still sneak back in through PAM even after you disable <code>PasswordAuthentication</code>.</div>
