<p><span class="c-light">The ticket:</span> secadmin has two compliance items. Password aging on <code>dev1</code>, <code>dev2</code>, <code>ops1</code>, and <code>dbadmin1</code>: expire every 90 days, at least 7 days between changes, 14 days warning, and force <code>dev1</code> to change at next login. And scoped sudo so <code>ops1</code> can run <code>systemctl</code>, <code>dnf</code>, and <code>firewall-cmd</code> with no password, but nothing else. Use <code>/etc/sudoers.d/</code> so it is reviewable, and validate the syntax before saving, because a sudoers lockout last quarter was a nightmare.</p>

<p><span class="c-light">The real problem:</span> a bad sudoers file can lock everyone out of privilege escalation. The whole point of this ticket is doing it the safe way, with validation.</p>

<p><span class="c-light">What we are doing:</span> password aging with <code>chage</code>, and a safe, scoped sudoers drop-in that is syntax-checked before it goes live.</p>

<h2 id="apply-aging" class="pp-h2">Apply the password policies in bulk</h2>

<p>Four accounts get the same policy, so loop over them. That is the real sysadmin move, and it is faster than four separate commands.</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot" style="background:#ff5f57"></div><div class="pp-code-dot" style="background:#febc2e"></div><div class="pp-code-dot" style="background:#28c840"></div></div><div class="pp-code-lang">bash</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`# see the current state\nfor u in dev1 dev2 ops1 dbadmin1; do echo "=== $u ==="; sudo chage -l $u; done\n\n# apply 90 / 7 / 14 to all four\nfor u in dev1 dev2 ops1 dbadmin1; do\n    sudo chage -M 90 -m 7 -W 14 $u\ndone\n\n# verify\nfor u in dev1 dev2 ops1 dbadmin1; do\n    echo "=== $u ==="; sudo chage -l $u | grep -E "Maximum|Minimum|Warning"\ndone`}</pre></div></div>

<h2 id="force-change" class="pp-h2">Force a password change on next login</h2>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot" style="background:#ff5f57"></div><div class="pp-code-dot" style="background:#febc2e"></div><div class="pp-code-dot" style="background:#28c840"></div></div><div class="pp-code-lang">bash</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`sudo chage -d 0 dev1\nsudo chage -l dev1    # 'password must be changed'`}</pre></div></div>

<p><code>-d 0</code> sets the last-change date to the epoch, so the system treats the password as immediately expired and prompts at next login.</p>

<h2 id="login-defs" class="pp-h2">System-wide defaults in login.defs</h2>

<p><code>chage</code> changes existing users. To set the policy for every future user, edit <code>/etc/login.defs</code>. This does not touch existing accounts.</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot" style="background:#ff5f57"></div><div class="pp-code-dot" style="background:#febc2e"></div><div class="pp-code-dot" style="background:#28c840"></div></div><div class="pp-code-lang">bash</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`grep -E "PASS_MAX_DAYS|PASS_MIN_DAYS|PASS_WARN_AGE" /etc/login.defs\n\nsudo cp /etc/login.defs /etc/login.defs.bak\nsudo sed -i 's/^PASS_MAX_DAYS.*/PASS_MAX_DAYS\\t90/' /etc/login.defs\nsudo sed -i 's/^PASS_MIN_DAYS.*/PASS_MIN_DAYS\\t7/' /etc/login.defs\nsudo sed -i 's/^PASS_WARN_AGE.*/PASS_WARN_AGE\\t14/' /etc/login.defs\ngrep -E "PASS_MAX_DAYS|PASS_MIN_DAYS|PASS_WARN_AGE" /etc/login.defs`}</pre></div></div>

<h2 id="sudoers-dropin" class="pp-h2">Build the sudoers.d drop-in</h2>

<p>Never edit <code>/etc/sudoers</code> directly with a plain editor. Write a drop-in to <code>/etc/sudoers.d/</code>, set its mode to 440, and validate with <code>visudo -c</code> before trusting it.</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot" style="background:#ff5f57"></div><div class="pp-code-dot" style="background:#febc2e"></div><div class="pp-code-dot" style="background:#28c840"></div></div><div class="pp-code-lang">bash</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`sudo bash -c 'cat > /etc/sudoers.d/ops1-scoped << "EOF"\n# scoped sudo for ops1: services, packages, firewall\nops1 ALL=(ALL) NOPASSWD: /usr/bin/systemctl, /usr/bin/dnf, /usr/bin/firewall-cmd\nEOF'\n\nsudo chmod 440 /etc/sudoers.d/ops1-scoped   # sudoers ignores it otherwise\nsudo visudo -c    # must report: parsed OK`}</pre></div></div>

<div class="pp-warn"><strong>warning:</strong> If <code>visudo -c</code> reports an error, fix it before you log out. A broken file in <code>/etc/sudoers.d/</code> can disable sudo for everyone. The 440 permission and the syntax check are the two things standing between you and last quarter's lockout.</div>
