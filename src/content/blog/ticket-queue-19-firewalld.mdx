<p>secadmin wants the firewall on server1 rebuilt from a clean sheet, and the rules map straight onto who should reach what. Web open to the world on 80 and 443. SSH only from the management subnet, 10.0.50.0/24, refused from everywhere else. A management UI on 8443 open to exactly one host, 10.0.50.5. Cockpit cracked open for a single one-hour maintenance window. And a snapshot of every rule for the change ticket. All permanent, reloaded after.</p>

<p>Two flags decide whether any of this survives. <code>--permanent</code> writes the rule to disk, <code>--reload</code> pushes the saved rules into the running firewall. Forget <code>--permanent</code> and the rule evaporates at the next reboot. Forget <code>--reload</code> and it sits on disk doing nothing while you swear the change is not working. You will type both more today than anything else.</p>

<h2 id="concept-review" class="pp-h2">Concept review. Zones and the two flags.</h2>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot" style="background:#ff5f57"></div><div class="pp-code-dot" style="background:#febc2e"></div><div class="pp-code-dot" style="background:#28c840"></div></div><div class="pp-code-lang">bash</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`man firewall-cmd\nman firewalld.richlanguage`}</pre></div></div>

<p>A packet is matched to a zone, usually by the interface or its source address, and the zone decides what is allowed through named services, ports, or rich rules. Anything not allowed is dropped. The default zone on RHEL 9 is <code>public</code>. The <code>trusted</code> zone allows everything, <code>drop</code> silently discards, and <code>block</code> rejects with a reply.</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot" style="background:#ff5f57"></div><div class="pp-code-dot" style="background:#febc2e"></div><div class="pp-code-dot" style="background:#28c840"></div></div><div class="pp-code-lang">the two flags you use constantly</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`--permanent   write the rule to disk, so it survives a reboot\n--reload      apply the on-disk rules to the running firewall\n\n# without --permanent the rule vanishes on reboot\n# without --reload a permanent rule does not take effect yet`}</pre></div></div>

<h2 id="web" class="pp-h2">Open HTTP and HTTPS</h2>

<p>Named services are easier than raw ports, because they already map to the standard port numbers. Add them permanently, then reload.</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot" style="background:#ff5f57"></div><div class="pp-code-dot" style="background:#febc2e"></div><div class="pp-code-dot" style="background:#28c840"></div></div><div class="pp-code-lang">bash</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`sudo firewall-cmd --permanent --zone=public --add-service=http\nsudo firewall-cmd --permanent --zone=public --add-service=https\nsudo firewall-cmd --reload\nsudo firewall-cmd --zone=public --list-services`}</pre></div></div>

<h2 id="ssh-rich" class="pp-h2">Restrict SSH with a rich rule</h2>

<p>This is the step people get subtly wrong. Adding a rich rule that allows SSH from one subnet does nothing if the global ssh service is still open, because that still lets anyone in. Remove the global allow first, then add the scoped rule.</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot" style="background:#ff5f57"></div><div class="pp-code-dot" style="background:#febc2e"></div><div class="pp-code-dot" style="background:#28c840"></div></div><div class="pp-code-lang">bash</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`sudo firewall-cmd --permanent --zone=public --remove-service=ssh\n\nsudo firewall-cmd --permanent --zone=public \\\n    --add-rich-rule='rule family="ipv4" source address="10.0.50.0/24" service name="ssh" accept'\n\nsudo firewall-cmd --reload\nsudo firewall-cmd --zone=public --list-rich-rules`}</pre></div></div>

<h2 id="timed" class="pp-h2">A timed rule for Cockpit</h2>

<p>A maintenance window wants a rule that cleans itself up. A timeout rule is runtime only, not permanent, and firewalld removes it automatically when the clock runs out.</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot" style="background:#ff5f57"></div><div class="pp-code-dot" style="background:#febc2e"></div><div class="pp-code-dot" style="background:#28c840"></div></div><div class="pp-code-lang">bash</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`sudo firewall-cmd --zone=public --add-service=cockpit --timeout=3600\nsudo firewall-cmd --zone=public --list-services\n# cockpit is removed from the runtime config automatically after an hour`}</pre></div></div>
