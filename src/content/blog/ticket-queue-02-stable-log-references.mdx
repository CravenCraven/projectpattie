<p><span class="c-light">The ticket:</span> logadmin1 has an audit log whose name keeps changing because of rotation. They want a stable reference to the current log that does not break when rotation renames the file, and the backup service needs the same thing. On top of that, last week someone deleted a file and the symlink pointing at it broke silently for two days. They want to know how to catch that.</p>

<p><span class="c-light">The real problem:</span> A filename is not a file. Once that idea lands, hard links and soft links stop being confusing and the whole ticket falls out of it.</p>

<p><span class="c-light">What we are doing:</span> Learning inodes, hard links, and symbolic links on real files, then building a proactive check for dead symlinks.</p>

<h2 id="concept-review" class="pp-h2">Concept review. What a filename really is.</h2>

<p>Read the manual pages first. These four are the whole toolkit for this ticket.</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot" style="background:#ff5f57"></div><div class="pp-code-dot" style="background:#febc2e"></div><div class="pp-code-dot" style="background:#28c840"></div></div><div class="pp-code-lang">bash</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`man ln\nman find\nman stat\nman readlink`}</pre></div></div>

<p>An <strong>inode</strong> is the file. It holds the permissions, the owner, and the pointers to the data blocks. A filename is just a label that points at an inode. That single fact explains both link types.</p>

<p><span class="c-cyan">Hard link:</span> another name for the same inode. Same inode number, same data. It survives the original name being deleted or renamed, because it was never pointing at the name, only at the inode. Hard links cannot cross filesystems and cannot point at a directory.</p>

<p><span class="c-cyan">Soft link, or symlink:</span> a tiny file that stores a path string. It has its own inode. If the path it stores is moved or deleted, the symlink is left pointing at nothing. Symlinks can cross filesystems freely and can point at directories.</p>

<h2 id="hard-link" class="pp-h2">The hard link. A reference that survives rotation.</h2>

<p>Set the scene, then link it. <code>ls -li</code> prints the inode number first so you can prove the two names are the same file.</p>

<p>Now simulate rotation by renaming the original, then read through the stable name.</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot" style="background:#ff5f57"></div><div class="pp-code-dot" style="background:#febc2e"></div><div class="pp-code-dot" style="background:#28c840"></div></div><div class="pp-code-lang">bash</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`sudo mv /srv/logs/audit/audit.log.20260503 /srv/logs/audit/audit.log.20260503.gz\ncat /srv/logs/audit/audit.current    # still works\nls -li /srv/logs/audit/`}</pre></div></div>

<p>The hard link followed the inode, not the name, and the inode did not move. That is the stable reference logadmin1 asked for.</p>

<h2 id="symlink" class="pp-h2">The symlink. A reference that can rot.</h2>

<p>A symlink is the right tool when you need to cross a filesystem or point at a directory. It is also brittle, and this is exactly the failure that bit them.</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot" style="background:#ff5f57"></div><div class="pp-code-dot" style="background:#febc2e"></div><div class="pp-code-dot" style="background:#28c840"></div></div><div class="pp-code-lang">bash</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`sudo ln -s /srv/logs/audit/audit.current /srv/logs/audit/backup.target\nreadlink /srv/logs/audit/backup.target    # shows the stored path\ncat /srv/logs/audit/backup.target         # works, for now\n\n# delete the target and watch the link go dead\nsudo rm /srv/logs/audit/audit.current\nls -l /srv/logs/audit/backup.target       # shown in red, dangling\ncat /srv/logs/audit/backup.target         # No such file or directory`}</pre></div></div>

<p>The link still exists. It just points at nothing. Nobody notices until they try to read it, which is how it went unseen for two days.</p>

<h2 id="detect-broken" class="pp-h2">Detecting broken symlinks</h2>

<p><code>find</code> has a filter built for this. <code>-xtype l</code> matches symlinks whose target does not resolve. Run it on a schedule and dead links surface the same day they break.</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot" style="background:#ff5f57"></div><div class="pp-code-dot" style="background:#febc2e"></div><div class="pp-code-dot" style="background:#28c840"></div></div><div class="pp-code-lang">bash</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`# every broken symlink under /srv\nsudo find /srv -xtype l 2>/dev/null\n\n# turn it into a report for logadmin1\nsudo mkdir -p /srv/audit_reports\nsudo find /srv -xtype l 2>/dev/null > /srv/audit_reports/broken_symlinks.txt\ncat /srv/audit_reports/broken_symlinks.txt`}</pre></div></div>

<h2 id="cp-vs-ln" class="pp-h2">cp versus ln, made concrete</h2>

<p>Worth seeing once so it never trips you up. <code>cp</code> makes a new inode, an independent copy. <code>ln</code> makes another name for the same inode.</p>
