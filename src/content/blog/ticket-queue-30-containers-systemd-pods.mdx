<p>cuser2 rebooted the box and the containers from yesterday simply did not come back. That is not a bug, it is the default: rootless containers are tied to the user's session and go away with it. cuser2 needs them starting at boot whether or not anyone is logged in, and while we are in there, the API stack, app plus redis plus postgres, wired together as a single podman pod so it can be managed as one thing.</p>

<p>Two facts explain both the disappearance and the fix. A rootless user's services die at logout unless <code>enable-linger</code> keeps their manager running, and a generated systemd unit that points at a container by ID breaks the instant you recreate that container. <code>enable-linger</code> plus the <code>--new</code> flag, which makes the unit rebuild the container from its spec, are the whole answer.</p>

<h2 id="concept-review" class="pp-h2">Concept review. Linger, units, and pods.</h2>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot" style="background:#ff5f57"></div><div class="pp-code-dot" style="background:#febc2e"></div><div class="pp-code-dot" style="background:#28c840"></div></div><div class="pp-code-lang">bash</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`man podman-generate-systemd\nman podman-pod\nman loginctl`}</pre></div></div>

<p>By default systemd stops a user's services at logout, so a rootless container dies with them. <code>enable-linger</code> keeps the user's manager running independently, so units start at boot and survive logout. A pod is a group of containers that share a network namespace, like a Kubernetes pod, reachable from each other over localhost, with a single set of port mappings defined on the pod.</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot" style="background:#ff5f57"></div><div class="pp-code-dot" style="background:#febc2e"></div><div class="pp-code-dot" style="background:#28c840"></div></div><div class="pp-code-lang">podman generate systemd flags</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`--new                 unit recreates the container from its spec at start\n--name NAME           generate for one container or pod\n--files               write .service files instead of stdout\n--restart-policy=always   restart on failure`}</pre></div></div>

<h2 id="linger" class="pp-h2">Enable linger and recreate the containers</h2>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot" style="background:#ff5f57"></div><div class="pp-code-dot" style="background:#febc2e"></div><div class="pp-code-dot" style="background:#28c840"></div></div><div class="pp-code-lang">bash</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`sudo loginctl enable-linger cuser2\nloginctl show-user cuser2 | grep -i linger    # Linger=yes\nmkdir -p ~/.config/systemd/user ~/webcontent ~/redis-data\necho "<h1>cuser2 web</h1>" > ~/webcontent/index.html\n\npodman run -d --name dev-web -p 8081:80 \\\n    -v ~/webcontent:/usr/share/nginx/html:ro,Z nginx:latest\npodman run -d --name dev-cache -p 6380:6379 \\\n    -v ~/redis-data:/data:Z redis:latest`}</pre></div></div>

<h2 id="units" class="pp-h2">Generate and enable systemd units</h2>

<p>Generate a portable unit for each container, then, and this is the step people miss, stop and remove the manually started container before enabling the unit, or systemd hits a name conflict trying to start its own copy.</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot" style="background:#ff5f57"></div><div class="pp-code-dot" style="background:#febc2e"></div><div class="pp-code-dot" style="background:#28c840"></div></div><div class="pp-code-lang">bash</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`cd ~/.config/systemd/user\npodman generate systemd --new --name dev-web --files --restart-policy=always\npodman generate systemd --new --name dev-cache --files --restart-policy=always\n\npodman stop dev-web dev-cache\npodman rm dev-web dev-cache\n\nsystemctl --user daemon-reload\nsystemctl --user enable --now container-dev-web.service\nsystemctl --user enable --now container-dev-cache.service\npodman ps`}</pre></div></div>

<h2 id="pod" class="pp-h2">Build the api-stack pod</h2>

<p>Create the pod with its port mappings, then add each container with <code>--pod</code>. The containers reach each other over localhost inside the pod.</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot" style="background:#ff5f57"></div><div class="pp-code-dot" style="background:#febc2e"></div><div class="pp-code-dot" style="background:#28c840"></div></div><div class="pp-code-lang">bash</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`podman pod create --name api-stack -p 8082:8080 -p 5433:5432\nmkdir -p ~/postgres-data\n\npodman run -d --pod api-stack --name api-db \\\n    -e POSTGRES_PASSWORD=secret -e POSTGRES_USER=apiuser -e POSTGRES_DB=apidb \\\n    -v ~/postgres-data:/var/lib/postgresql/data:Z postgres:latest\npodman run -d --pod api-stack --name api-redis redis:latest\npodman run -d --pod api-stack --name api-app \\\n    -v ~/webcontent:/usr/share/nginx/html:ro,Z nginx:latest\n\npodman pod ps\npodman ps --pod`}</pre></div></div>

<h2 id="pod-units" class="pp-h2">Systemd units for the pod</h2>

<p>Generating from the pod name writes a unit for the pod and one for each container, and the pod unit pulls in the container units. Stop the manual pod first, then enable.</p>

<div class="pp-code"><div class="pp-code-head"><div class="pp-code-dots"><div class="pp-code-dot" style="background:#ff5f57"></div><div class="pp-code-dot" style="background:#febc2e"></div><div class="pp-code-dot" style="background:#28c840"></div></div><div class="pp-code-lang">bash</div><button class="pp-code-copy" onclick="navigator.clipboard.writeText(this.closest('.pp-code').querySelector('pre').textContent);this.textContent='copied!';setTimeout(()=>this.textContent='copy',1500)">copy</button></div><div class="pp-code-body"><pre>{`cd ~/.config/systemd/user\npodman generate systemd --new --name api-stack --files --restart-policy=always\nls pod-* container-api-*\n\npodman pod stop api-stack\npodman pod rm api-stack\n\nsystemctl --user daemon-reload\nsystemctl --user enable --now pod-api-stack.service\npodman pod ps; podman ps`}</pre></div></div>
